# Python Sidekick Guidelines for Gemini

## Overview

`internal/sidekick/python` is the native Go code generator in Librarian for Google Cloud Python client libraries. It generates idiomatic, production-grade Python GAPIC client code from `api.API` models using Mustache templates and decomposed annotations, achieving parity with legacy `gapic-generator` output.

## Architectural Invariants

1. **Decomposed Annotators (1:1 with Tests)**:
   - Dedicated source file per AST node type: `annotate_model.go`, `annotate_service.go`, `annotate_method.go`, `annotate_message.go`, `annotate_field.go`, `annotate_oneof.go`, `annotate_enum.go`, `annotate_enum_value.go`.
   - Each annotator file must be paired 1:1 with a matching `_test.go` file (`annotate_model_test.go`, etc.).
   - `annotate_model.go` acts as the coordinator, annotating messages and enums first before services.

2. **Template-First Emission**:
   - Zero in-Go Python syntax generation. Never assemble Python classes, methods, docstrings, decorators, or routing matchers via `strings.Builder` or `fmt.Sprintf`.
   - Mustache templates (`templates/*.mustache`) and reusable partials own all syntax, formatting, and docstrings.
   - Standard Apache 2.0 license and file banners are defined in `templates/partials/prologue.mustache` and included via `{{> partials/prologue}}`.

3. **Parser & AST Fidelity**:
   - Never re-parse `.proto` files with regex, custom tokenizers, or filesystem AST walks.
   - All comments, locations, types, and routing annotations are obtained directly from `internal/sidekick/parser` via `api.API`.

4. **Output Hermeticity**:
   - All generated files must be contained strictly under `outdir`. Escaping `outdir` via `..` paths is strictly forbidden.

5. **Hermetic & Non-Vacuous Testing**:
   - Golden integration tests reside in `testdata/` and compare full file contents with `cmp.Diff`.
   - Never branch on test fixture names (e.g. `redis`, `credentials`) in production code.
   - Never use test helpers (e.g., `api.NewTestAPI`) on production execution paths.

## Formatting & Linters

Python source generated by Sidekick is formatted with `ruff`:

```bash
# Format Python code
ruff format <directory>

# Lint and auto-fix Python code
ruff check --fix <directory>
```

## Go Verification Workflow

When modifying `internal/sidekick/python`:

```bash
# Format Go code
gofmt -s -w internal/sidekick/python

# Organize imports
go tool goimports -w internal/sidekick/python

# Run linter
go tool golangci-lint run ./internal/sidekick/python/...

# Run unit tests
go test -v ./internal/sidekick/python/...

# Run race detector
go test -race ./internal/sidekick/python/...
```
